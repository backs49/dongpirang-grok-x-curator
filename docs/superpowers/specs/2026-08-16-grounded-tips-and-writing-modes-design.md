# 근거 기반 팁 생성과 글쓰기 모드 확장 설계

날짜: 2026-08-16  
상태: 사용자 승인 완료 — 구현 전 문서 검토 대기

## 목표

아이디어 탭에 다음 두 가지를 추가한다.

1. `빌더 노트`를 기본 글쓰기 모드로 추가하고, 자동 믹스의 다섯 번째 카드로 사용한다.
2. 신뢰 가능한 웹 근거와 선택 입력한 사용자 참고 자료를 바탕으로 `일상·건강·금융·IT 빌더` 팁을 생성한다.

이 기능은 일반 아이디어 생성의 속도와 독립성을 유지하면서, 사실성이 중요한 팁만 Grok CLI의 웹 검색·가져오기 도구를 사용한다.

## 확정된 글쓰기 모드 정책

### 기본 자동 믹스

자동 믹스의 아이디어 1~5는 아래 순서로 고정 배정한다.

1. 진지/분석
2. 유머
3. 스토리텔링
4. 어그로/후킹
5. 빌더 노트

`풍자`는 자동 믹스에서 제외한다. 모드 이름은 바꾸지 않는다.

### 빌더 노트 카드

- 직접 만든 것·실험·실패·관찰 중 한 장면에서 시작한다.
- 구체적인 변화, 수치, 오류, 제약 중 하나를 포함한다.
- "해결법"을 과장해 가르치지 않고, 관찰이나 담담한 결말로 닫는다.
- 17년차 IT 직장인·인디 개발자라는 기존 보이스 카드의 1인칭 경험 기반 페르소나를 유지한다.

### 실험실

`풍자`, `하오체`, `한강체`를 실험실 그룹에 표시한다. 숨김이나 삭제가 아니라 직접 선택 가능한 모드다. 자동 믹스만 이 모드를 선택하지 않는다.

- 김훈체와 헤밍웨이체는 통합하지 않고 모두 유지한다.
- 기존 작가/인물 모드의 이름도 유지한다.
- `한강체`는 절제된 감각, 조용한 장면, 설명하지 않는 마무리를 카드 규칙으로 정의하고 실험실에 추가한다.

## 사용자 경험

아이디어 탭의 키워드 입력 아래에 `콘텐츠 유형` 선택을 둔다.

| 유형 | 동작 |
|---|---|
| 일반 아이디어 (기본) | 현재와 같은 검색 없는 생성. 선택한 글쓰기 모드와 길이를 적용한다. |
| 근거 기반 팁 | Grok CLI가 웹을 조사하고 출처를 확인한 뒤 팁을 생성한다. |

근거 기반 팁을 선택하면 다음 입력을 추가로 보여 준다.

- `팁 분야`: 일상, 건강, 금융, IT 빌더
- `참고 메모·링크` (선택): 사용자가 알고 있는 사실, 기사/공식 문서 URL, 원하는 독자층, 문제 상황

사용자 입력은 곧바로 사실로 취급하지 않는다. 검색 질의를 보강하는 참고 재료이며, 최종 주장에는 아래의 출처 검증 규칙을 적용한다.

글쓰기 모드 선택은 근거 기반 팁에서도 모든 모드에 열어 둔다. 단, 문체는 표현에만 작용하며, 사실·수치·권고의 근거는 문체 적용 전후에 검증한다.

## 근거 수집과 생성 흐름

```text
주제 + 선택 참고 메모/링크
        ↓
Grok CLI: web_search + web_fetch 전용 조사
        ↓
신뢰 출처 2개 이상에서 확인되는 사실 추출
        ↓
사실 골격과 출처 메타데이터 확정
        ↓
선택한 글쓰기 모드로 X 포스트 5개 생성
        ↓
사실 재검증 → 본문·출처 카드·확인일 저장
```

### Grok CLI 경로

일반 `GrokCliProvider`는 현재 `--tools ""`로 도구를 차단한다. 이를 바꾸지 않고, 근거 기반 팁 전용 실행 경로를 분리한다.

- `grok -p` 헤드리스 실행
- 허용 도구: `web_search`, `web_fetch`만
- `--no-memory` 유지
- 제한된 최대 턴 수와 타임아웃 사용
- 명령 실행·파일 편집·MCP·하위 에이전트 도구는 허용하지 않는다.

Grok Build TUI 1.0.3의 헤드리스 도구 필터와 스트리밍 JSON 출력을 사용해 검색 도구 결과에서 제목, URL, 발행/확인일, 발췌를 수집한다. 보통 생성에는 기존의 도구 없는 빠른 CLI 경로를 유지한다.

### 출처 기준

- 서로 다른 도메인의 근거 2개 이상이 있어야 한다.
- 공식 기관, 규제 기관, 학회, 대학/연구기관, 제품의 공식 문서와 릴리스 노트를 우선한다.
- 사용자 제공 링크는 위 기준을 통과한 경우에만 근거가 된다.
- 검색 결과가 서로 상충하거나, 날짜·원문을 확인할 수 없거나, 근거가 두 개에 못 미치면 팁을 생성하지 않는다.
- 저장되는 각 결과에는 `sources`, `verified_at`, `topic_category`, `user_references` 메타데이터를 포함한다.

## 건강·금융 범위와 안전선

건강과 금융은 일반 독자용 정보로 제공한다. 사용자의 증상, 병력, 복용 약, 소득, 부채, 보유 종목 등을 받아 개인별 행동을 결정하지 않는다.

| 분야 | 포함 | 제외 |
|---|---|---|
| 건강 | 생활습관, 예방, 공공 건강 정보 | 진단, 치료 선택, 복약량·약물 변경, 응급 판단 |
| 금융 | 금융 기초, 제도, 소비자 보호, 사기 예방 | 종목 매수·매도, 개인별 자산 배분, 수익 보장·예측 |

근거 기반 건강·금융 결과의 모든 카드에는 출처와 확인일, "일반 정보이며 개인 상황은 전문가와 확인" 안내를 표시한다. 문체 모드는 선택할 수 있지만, 출처 없는 의료·금융 주장이나 개인 맞춤 권고가 검출되면 결과를 보류한다.

## 데이터와 오류 처리

- 근거 기반 작업도 기존 영속 작업 큐를 사용해 모바일 연결이 끊겨도 완료한다.
- 작업 요청에는 콘텐츠 유형, 팁 분야, 사용자 참고 자료, 모드를 저장한다.
- 검색 또는 생성 실패 시 상태를 `failed`로 남기고, 이전 결과를 지우지 않는다.
- 출처 부족은 모델 오류가 아닌 명시적인 `insufficient_sources` 상태로 표시하고 재시도를 안내한다.
- 일반 아이디어 이력과 근거 기반 팁 이력은 모두 기존 `ideas_history`에 저장하되, 근거 기반 결과만 출처 확장 필드를 갖는다. 기존 이력은 하위 호환으로 그대로 읽는다.

## 구현 단위

| 단위 | 책임 |
|---|---|
| `writing_modes.py` | 빌더 노트·한강체 카드, 자동 믹스 배정, 기본/실험실 그룹 메타데이터 |
| `tabs/tab_ideas.py` | 콘텐츠 유형·팁 분야·참고 자료 UI, 모드 그룹 표시, 근거 카드 렌더링 |
| `idea_jobs.py` / `idea_job_runner.py` / `scripts/idea_worker.py` | 확장된 작업 입력과 근거 기반 작업의 영속 실행 |
| `providers/grok_cli.py` 또는 별도 연구 모듈 | 웹 도구만 허용하는 Grok CLI 조사, 스트리밍 출력의 출처 추출 |
| `grok_client.py` | 조사 결과 검증, 사실 골격 기반 포스트 생성, 기존 아이디어 스키마와 결합 |
| `xalgo_prompts.py` | 빌더 노트·한강체·근거 기반 생성/안전 프롬프트 |
| `ideas_history.py` / `i18n.py` | 출처 메타데이터·복원과 한국어/영어/일본어 UI 문구 |

## 검증 계획

- 모드 카드: 빌더 노트·한강체 완결성, 실험실/기본 그룹, 자동 믹스에서 풍자 제외와 빌더 노트 포함
- UI: 일반/근거 기반 전환, 팁 분야와 참고 자료의 작업 전달, 실험실 직접 선택
- Grok CLI: 일반 경로는 도구 없음, 조사 경로는 `web_search,web_fetch`만 허용
- 출처 파서: 서로 다른 도메인 2개, 중복/누락/상충/URL 없는 경우 거절
- 생성: 사용자 참고 자료가 검색 질의에는 포함되지만 검증 전에는 사실로 출력되지 않음
- 안전선: 건강의 진단·복약 지시, 금융의 종목 추천·개인 자산 배분 요청을 보류
- 회귀: 기존 일반 아이디어 생성, 영속 작업 큐, 이력 복원, 데모 모드가 유지됨

## 스코프 제외

- 개인 건강·금융 프로필 수집과 개인화 권고
- 의료·금융 전문가 상담을 대신하는 기능
- 모든 웹사이트를 동등하게 신뢰하는 자동 수집
- 일반 아이디어 생성에 웹 검색을 강제해 속도와 비용을 높이는 변경
